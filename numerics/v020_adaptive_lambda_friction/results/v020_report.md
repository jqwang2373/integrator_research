# v020 Experiment Report

Generated by `run_v020.py`.

## Purpose

- Combine v015's embedded adaptive Gauss64 controller with v019's multiplier-dependent Stribeck-style friction residual.
- Test whether adaptive stepping improves high-accuracy lambda-dependent sharp-friction cases more efficiently than globally halving the fixed Gauss6 step.
- JAX kernels are warmed before timed fixed/adaptive runs.

## Results

- `lambda_smooth` baseline Gauss6 h=0.025: error 4.350e-11, runtime 0.390s.
- `lambda_smooth` finer fixed Gauss6 h=0.0125: error 6.319e-13, runtime 0.837s.
- `lambda_smooth` best adaptive: `adaptive_lambda_gauss64_tol1e-07` error 1.917e-10, runtime 0.677s, accepted/rejected 33/3, h range [2.950e-03, 3.555e-02].
- `lambda_smooth` best adaptive ratios: error/runtime vs Gauss6 h=0.025 = 4.41e+00/1.74e+00; error/runtime vs Gauss6 h=0.0125 = 3.03e+02/8.09e-01.
- `lambda_smooth` best adaptive value ratio against fixed h=0.0125: 4.07e-03 (above 1 would mean lower error per extra runtime than global halving).
- `lambda_smooth` no adaptive tolerance beat Gauss6 h=0.025 while staying within 1.25x runtime.
- `lambda_smooth` conclusion: adaptive is not the right default here; the fixed Gauss6 coarse step is already more accurate.
- `lambda_sharp` baseline Gauss6 h=0.025: error 3.249e-07, runtime 0.421s.
- `lambda_sharp` finer fixed Gauss6 h=0.0125: error 1.381e-08, runtime 0.844s.
- `lambda_sharp` best adaptive: `adaptive_lambda_gauss64_tol1e-07` error 2.666e-10, runtime 0.991s, accepted/rejected 45/8, h range [1.266e-03, 3.596e-02].
- `lambda_sharp` best adaptive ratios: error/runtime vs Gauss6 h=0.025 = 8.21e-04/2.35e+00; error/runtime vs Gauss6 h=0.0125 = 1.93e-02/1.17e+00.
- `lambda_sharp` best adaptive value ratio against fixed h=0.0125: 4.41e+01 (above 1 would mean lower error per extra runtime than global halving).
- `lambda_sharp` fastest adaptive better than Gauss6 h=0.025 within 1.25x runtime: `adaptive_lambda_gauss64_tol1e-05` with error 6.500e-08 and runtime 0.459s.
- `lambda_sharp` conclusion: adaptive is a real win; it beats globally halving Gauss6 by 51.8x in error at 1.17x runtime.

## Interpretation

- Adaptive lambda-Gauss64 tests whether the v015 near-nonsmooth strategy survives the more realistic v019 friction/multiplier coupling.
- The smooth lambda-friction case is not an adaptive-step win in this benchmark: fixed Gauss6 h=0.025 is already extremely accurate and cheaper than driving an embedded controller to comparable tolerances.
- The sharp lambda-friction case is the useful target: adaptive stepping can spend small steps near the high-curvature friction transition and larger steps elsewhere, so it can beat the coarse fixed Gauss6 run at similar runtime.
- If the adaptive value ratio against fixed h=0.0125 stays below one, global halving is still the simpler high-accuracy choice for that case; adaptive is then a practical coarse-step improvement rather than the final accuracy-per-cost winner.
- The method is still a smooth regularized-friction strategy; it is not a complementarity/contact solver.
