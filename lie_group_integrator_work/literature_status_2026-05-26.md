# Literature Status and Decision Log, 2026-05-26

Primary paper:
- Chaturvedi, Sandu, Sandu, "Higher-order integration of index-3 DAE with friction using time finite elements on Lie groups", published 2026-03-02 in Multibody System Dynamics.
- Source: https://link.springer.com/article/10.1007/s11044-026-10153-w

Forward citations:
- Web searches for the exact title and DOI on 2026-05-26 did not expose reliable papers citing this article. The paper is very new, so current exploration follows its references and adjacent high-order Lie-group integrator literature.

Reference trail most relevant to this workspace:
- SBEL/Negrut rA baseline: Kissel, Negrut, Taves ASME 2021 and JCNLD 2022 work on rotation-matrix absolute-coordinate multibody dynamics. Reproducible code is kept locally under `../external/sbel-reproducibility/2021/ASME/rA-formulation`.
- Munthe-Kaas 1998/1999: high-order Runge-Kutta methods on Lie groups/manifolds. This motivates the v002/v004 `rkmk4` baseline.
- Wieloch and Arnold 2021: BDF integrators for constrained mechanical systems on Lie groups. This is directly relevant to index-3 constrained mechanics, but the local experiments have not yet implemented BLieDF.
- Bogfjellmo and Marthinsen: high-order symplectic partitioned Lie group methods. Source: https://arxiv.org/abs/1303.5654
- Gauss collocation and invariant preservation are relevant because the v005 candidate uses a two-stage Gauss solve for the body angular velocity. Source context: https://epubs.siam.org/doi/10.1137/110856617
- RATTLie: a variational Lie group integration scheme for constrained mechanical systems. Source: https://www.sciencedirect.com/science/article/pii/S0377042719304959
- 2025 sigma-modified Lie group generalized-alpha methods for constrained multibody systems. The search result highlights second-order constrained accuracy, zero stability, improved accuracy versus the original geom1 method, and lower implementation cost. Source: https://www.sciencedirect.com/science/article/pii/S0094114X25003258
- Tumiotto and Arnold 2024 half-explicit Lie group Runge-Kutta/local-coordinate approach for constrained Cosserat rods. It is relevant as a lower-Newton-cost constrained Lie integrator family, though its target problem differs from frictional rigid MBD. Source: https://link.springer.com/article/10.1007/s11044-024-10002-8

Experimental decision so far:
- v003 establishes that the SBEL/Negrut rA code path is reproducible in a modern Python stack, but the tested dynamics behavior is roughly first order.
- v004 shows a fourth-order structure-preserving path with `lie_midpoint_yoshida4`, but the negative Yoshida substep is a bad fit for nonsmooth friction/contact.
- v005 is the current best smooth-mechanics candidate: `gauss_lie4` keeps fourth-order behavior, preserves quadratic invariants to solver tolerance, has much smaller spatial momentum drift than v004, and avoids backward composition substeps.
- v006 moves the same candidate to a fixed-pivot rigid-body DAE prototype. The holonomic constraint `r + R s = 0` is enforced by reduction, the pivot reaction/Lagrange multiplier is recovered, and DAE residuals are checked. This is still not a general absolute-coordinate Newton solve, but it is closer to the paper's constrained pendulum setting than v005.
- v007 implements an absolute-coordinate two-stage Gauss-Lie stage solve with explicit Lagrange multipliers. A position-only stage constraint fails; position+velocity improves but remains low order; position+velocity+acceleration consistency recovers near-fourth-order behavior. This is an important index-3 DAE lesson aligned with the paper's emphasis on DAE-level integration rather than ODE-only Lie updates.
- v008 adds endpoint algebraic variables and constraints to the nonlinear solve, removing v007's endpoint projection for the fixed-pivot prototype. The endpoint-constrained method keeps the same near-fourth-order behavior while enforcing endpoint position/velocity constraints inside Newton.
- v009 adds a regularized friction torque to both the reduced reference ODE and the absolute-coordinate rotational residual. Smooth friction (`eps=0.50`) keeps the endpoint-constrained method near fourth order, while sharper Coulomb-like regularization (`eps=0.05`) reduces the measured order to roughly 2-2.5. Endpoint constraints and dissipative energy behavior remain clean in both cases.
- v010 replaces the finite-difference Newton Jacobian in v009 with a JAX automatic-differentiation Jacobian for the same 54-variable endpoint residual. The AD Jacobian preserves the finite-difference solution to roundoff-level final-state agreement and gives roughly 30-40x warm runtime speedups in the fixed-pivot friction benchmark. This supports the paper's emphasis on AD-friendly Jacobian construction, although v010 is still an SO(3) local-vector prototype rather than the paper's explicit quaternion `S^3` transport formulation.
- v011 implements the explicit quaternion transport operator used by the paper. Analytic `T_exp = d(exp(theta/2) p0)/dtheta` matches direct AD at roundoff scale, and the transported `Pi(g)=g_p T_exp + g_theta` and `Theta(g)=[g_r, Pi(g)]` match direct composite AD for a nonlinear friction-like load at max absolute error 2.429e-15. This closes the operator-level gap left by v010.
- v012 embeds a quaternion `S^3` attitude update into the endpoint-constrained frictional DAE residual. It uses the right-action counterpart `p(theta)=p0 exp(theta/2)` so it is algebraically comparable with the prior `R exp(theta)` SO(3) update. The quaternion residual matches v010's final states to roundoff scale, keeps unit norm at about 1e-16, and reproduces the v009/v010 smooth-friction fourth-order and sharp-friction order-reduction behavior.
- v013 adds a three-stage Gauss-Legendre sixth-order endpoint collocation candidate on the v012 quaternion residual. In the smooth regularized-friction case it reaches observed orientation order 5.994, reducing h=0.025 orientation error by roughly four orders of magnitude versus Gauss4 at only 1.15x runtime. In the sharper friction case, both Gauss4 and Gauss6 remain order-limited near 2.7, so higher smooth collocation order is not enough to solve near-nonsmooth friction order reduction.
- v014 sweeps the friction regularization width to turn that conclusion into a decision rule. Gauss6 is a strong win for `eps=1.0, 0.5, 0.2`, where it reduces h=0.025 orientation error by 2.40e+02x to 1.17e+04x versus Gauss4 at only 1.30-1.73x runtime. It remains useful at `eps=0.1`, but becomes only marginal at `eps=0.05` and `eps=0.025`. This is the current best local argument for why the Gauss6 quaternion endpoint candidate is better than the paper's finite-difference TFE direction in the smooth-friction regime: it combines the paper's `S^3` Jacobian insight with AD and a measured sixth-order collocation residual. The argument explicitly does not cover near-nonsmooth friction/contact, where regularity rather than nominal order is the limiting factor.
- v015 tests an embedded adaptive Gauss6/Gauss4 endpoint controller in the near-nonsmooth regularized-friction regime. It warms JAX kernels before timing. Adaptive Gauss64 is not a universal cheap replacement for fixed Gauss6 h=0.025, but it is better for high-accuracy sharp-friction targets: at `eps=0.05`, adaptive `tol=1e-6` reaches 8.713e-09 orientation error in 0.472s versus fixed Gauss6 h=0.0125 error 3.189e-08 in 0.552s; at `eps=0.025`, adaptive `tol=1e-6` reaches 3.538e-08 in 0.547s versus fixed h=0.0125 error 1.762e-07 in 0.659s.
- v016 adds a reduced right-action Lie-trapezoidal baseline to connect more directly with the paper's trapezoidal comparison. This is deliberately favorable to trapezoidal because it reconstructs fixed-pivot constraints exactly. The result still strongly favors Gauss6: at h=0.025, Gauss6 has 4.84e+07x lower orientation error in the frictionless case, 4.16e+07x lower in smooth friction, and 8.57e+02x lower in sharp friction. In a 20s frictionless h=0.05 long run, Gauss6 max relative energy error is 1.105e-10 versus 4.299e-04 for Lie-trapezoidal.
- v017 adds a reduced right-action Lie-BDF2 baseline to test the BLieDF/BDF reference direction on the same reduced quaternion problem. BDF2 is a cheap dissipative second-order method, but not a better high-accuracy candidate. At h=0.025, Gauss6 has 1.87e+08x lower orientation error in the frictionless case, 1.60e+08x lower in smooth friction, and 3.20e+03x lower in sharp friction. In a 20s frictionless h=0.05 long run, BDF2 changes energy by -5.314e-02 while Gauss6 changes energy by -2.922e-11. In sharp-friction long runs all methods dissipate energy, but BDF2 over-dissipates relative to Gauss6/trapezoidal.
- v018 adds reduced Lie-Lobatto endpoint-node collocation to test the paper's Gauss-Lobatto/TFE node direction before implementing a full absolute-coordinate TFE residual. Lobatto4 and Lobatto6 reach the expected fourth/sixth order in frictionless and smooth-friction cases. Lobatto6 is accuracy-competitive with Gauss6 but not better on accuracy-per-cost: in smooth friction h=0.025, Lobatto6 orientation error is 1.161e-11 versus Gauss6 1.579e-11, but runtime is 0.631s versus 0.149s; in sharp friction h=0.025, Gauss6 is both more accurate and faster, 7.566e-07 in 0.131s versus Lobatto6 9.131e-07 in 0.601s.
- v019 adds a lambda/reaction-load dependent Stribeck-style friction torque directly to the quaternion endpoint DAE residual, making the friction term depend on the stage Lagrange multiplier. This directly tests the paper's nonlinear friction Jacobian motivation. JAX differentiates the coupled residual without a hand-derived friction/multiplier Jacobian. In smooth lambda-friction, Gauss6 reaches orientation order 5.410 and h=0.025 orientation error 4.350e-11 versus Gauss4 1.634e-07, a 3.76e+03x reduction at 1.20x runtime. In sharp lambda-friction, order reduction persists but Gauss6 still cuts h=0.025 error by 3.19x at 1.23x runtime. Dissipation runs show zero measured positive step energy increase and negative stage friction power.
- v020 combines v015's embedded adaptive Gauss6/Gauss4 controller with v019's multiplier-dependent friction residual. The result is more selective than v015: smooth lambda-friction does not need adaptivity, because fixed Gauss6 h=0.025 is already more accurate than adaptive `tol=1e-7` while using less time. Sharp lambda-friction does benefit: adaptive `tol=1e-7` reaches 2.666e-10 orientation error in 0.991s versus fixed Gauss6 h=0.0125 error 1.381e-08 in 0.844s, a 51.8x error reduction at 1.17x runtime. A looser `tol=1e-5` also beats coarse fixed Gauss6 h=0.025 by about 5.00x in error within 1.09x runtime. This is the strongest current local evidence that the "better than the paper" path is not only higher smooth order, but an AD-enabled quaternion residual plus embedded adaptivity targeted at friction-transition intervals.
- v021 replaces the v019 Gaussian/tanh friction curve with a Brown-McPhee-style continuous velocity model: a `tanh(4v/v_s)` Coulomb term, the rational stiction/Stribeck bump, and viscous friction. The reaction-load norm from the stage Lagrange multiplier still scales the friction magnitude, so this remains a direct test of AD through coupled friction/multiplier residuals. In the smooth Brown-McPhee case, fixed Gauss6 stays the clean high-accuracy default: h=0.0125 gives 1.088e-11 orientation error, while adaptive `tol=1e-7` gives 2.528e-10. In the sharp Brown-McPhee case, fixed-step order reduction is strong (Gauss6 observed orientation order 2.901), but adaptive `tol=1e-7` reaches 1.186e-07 orientation error versus fixed Gauss6 h=0.0125 error 5.128e-07, a 4.3x reduction at 1.77x runtime. This narrows the model-fidelity gap relative to the paper, though the local model is still a componentwise fixed-pivot surrogate rather than the exact revolute-joint Brown-McPhee implementation.
- v022 adds a paper-like one-DOF revolute pendulum Brown-McPhee benchmark. It is still reduced rather than a full absolute-coordinate index-3 DAE, but it removes the componentwise 3D fixed-pivot surrogate from v021: the revolute angle maps to a unit quaternion via `p(q)=exp(e_y q/2)`, and Brown-McPhee friction depends on the pivot reaction norm, which depends on stage acceleration. In the smooth revolute Brown-McPhee case, fixed Gauss6 reaches observed angle order 5.773 and ties adaptive at high accuracy: fixed h=0.00625 gives 2.840e-12 angle error versus adaptive `tol=1e-8` at 2.766e-12. In the sharp revolute Brown-McPhee case, fixed-step order reduces to 2.412, but adaptive `tol=1e-7` reaches 3.072e-11 angle error versus fixed Gauss6 h=0.00625 error 3.246e-07, while also running faster in the recorded run. This is the clearest current evidence that the proposed path should be fixed high-order Gauss collocation for smooth velocity friction, plus embedded adaptivity around sharp friction-transition intervals.
- v023 upgrades the v022 revolute pendulum from a reduced scalar coordinate to an absolute-coordinate quaternion DAE with five explicit revolute constraints: fixed pivot plus hinge-axis alignment. The residual includes stage `r,u,v,w,a,alpha,lambda`, and Brown-McPhee friction is scaled by the stage reaction-force norm, so JAX differentiates through the same friction/multiplier coupling that motivates the paper's generalized `Pi`/`Theta` operator. This is not yet the best formulation because it intentionally does not endpoint-project: endpoint velocity drift remains visible. Still, the robustness signal is strong. In the smooth case, Gauss6 h=0.0125 gives 1.111e-07 orientation error versus Gauss4's 6.306e-01. In the sharp Brown-McPhee case, Gauss6 h=0.0125 gives 4.473e-07 while Gauss4 fails at h=0.025 and h=0.0125. So v023 says: for the full absolute-coordinate revolute DAE, higher-stage Gauss collocation is much more robust than the lower-stage method, but the next improvement must be index-3 endpoint/velocity/acceleration constraint treatment rather than simply adding more stages.
- v024 tests the direct Gauss-Lobatto/TFE-inspired node change on the v023 full revolute residual. Because Lobatto includes `c=0`, it first adds zero-safe JAX quaternion exponential and right-Jacobian inverse code to avoid undefined AD through `norm(u)` at zero local rotation. Even with that fix and a damped rank-deficient Newton fallback, direct Lobatto4 and Lobatto6 fail on every smooth and sharp fixed-step run. The Gauss6 baseline still succeeds with the same smooth h=0.0125 orientation error 1.111e-07 and sharp h=0.0125 orientation error 4.473e-07. This is an important negative result relative to the paper: Gauss-Lobatto nodes are not a drop-in improvement for the full index-3 revolute residual. The paper's TFE direction likely depends on its weighted-residual algebraic construction, not just endpoint collocation nodes.
- v025 tests a more classical constrained-integrator repair: SHAKE/RATTLE-style endpoint projection after the full absolute-coordinate Gauss stage solve. The projection maps the endpoint orientation back to the revolute manifold, sets tangent angular velocity, and reconstructs `r` and `v`, while keeping the stage friction/multiplier residual unchanged. It exactly removes endpoint position/velocity drift. In the sharp Brown-McPhee case it also rescues Gauss4 convergence at h=0.025 and h=0.0125, where raw Gauss4 fails. The tradeoff is accuracy: projected Gauss6 h=0.0125 has sharp-case orientation error 3.899e-06 versus raw Gauss6 1.389e-06 relative to the projected fine-step reference. So projection is a practical robustness/constraint-closure repair, but not the final high-order index-3 formulation.
- v026 moves part of that repair inside the nonlinear residual while keeping the system square. The `pivotvc` methods replace stage `r` collocation with the pivot velocity constraint, retaining pivot position and hinge-axis position constraints. This directly attacks the endpoint velocity drift seen in v023 without step-after projection. The improvement is large: in the smooth h=0.0125 case, Gauss6 endpoint velocity drift drops from 2.663e-03 to 6.897e-08; in the sharp h=0.0125 case, it drops from 2.325e-03 to 9.580e-08. It also rescues Gauss4 in the sharp h=0.025 and h=0.0125 runs where raw Gauss4 fails. This is the best current full absolute-coordinate revolute residual repair, though it is still partial lower-pair consistency rather than the full velocity/acceleration/TFE treatment.
- v027 strengthens the v026 square residual by also replacing stage `v` collocation with the pivot acceleration constraint. In the smooth h=0.0125 case, Gauss6 PivotVA reduces endpoint velocity drift to 5.213e-13; in the sharp h=0.0125 case it reduces it to 1.570e-12. Stage pivot acceleration is enforced at about 1e-15, and the Gauss6 orientation error is essentially unchanged relative to PivotVC. Sharp Gauss4 still succeeds where raw Gauss4 fails. This is the best current non-projection full absolute-coordinate revolute DAE consistency repair, with the limitation that it proves the pivot acceleration part on one revolute pendulum rather than a complete lower-pair/TFE treatment.
- v028 adds a constant off-axis body torque and a FullVA residual that explicitly enforces hinge-axis velocity and acceleration components while keeping the revolute Newton system square. The constrained-axis multipliers balance the off-axis torque, and FullVA reduces stage axis acceleration diagnostics from roughly 1e-12 under PivotVA to roughly 1e-25. However, the trajectory is unchanged relative to PivotVA. This is useful neutral evidence: the one-DOF revolute benchmark is no longer exposing axis-consistency as the bottleneck, so further progress should move to multi-joint/general lower-pair constraints or a true TFE weighted-residual treatment.
- v029 moves to a two-body double-revolute absolute-coordinate DAE with Brown-McPhee friction at both the ground and interbody hinges. This is the first local test where the v027 PivotVA repair is applied to an interbody revolute joint. In the smooth h=0.02 Gauss6 run, PivotVA reduces endpoint velocity drift from raw 1.807e-04 to 7.745e-13 and cuts orientation error from 4.105e-09 to 2.111e-09. In the sharp h=0.02 Gauss6 run, PivotVA reduces endpoint velocity drift from raw 1.279e-04 to 1.107e-11 while preserving trajectory error. FullVA drives axis acceleration diagnostics to about 1e-26 but does not change trajectory relative to PivotVA. The cost wall is now visible: Gauss6 double-revolute runs take several seconds because each Newton Jacobian is 138 by 138.
- v030 diagnoses the v029 cost wall by extracting converged first-step Newton Jacobians for smooth/sharp friction, raw/PivotVA/FullVA residuals, and Gauss4/Gauss6 stages. The Gauss6 FullVA Jacobians are 138 by 138 and only about 3.06% dense. In the recorded smooth case, dense linear solve time is 2.419e-01s versus 1.193e-04s for CSR `spsolve`; in the recorded sharp case, dense solve time is 3.126e-01s versus 5.668e-04s for CSR `spsolve`. This does not change the formulation, but it makes sparse/block Newton linear algebra the immediate engineering target.
- v031 integrates the v030 sparse linear solve into the actual v029 double-revolute Newton loop. On targeted h=0.02, T=0.10 tests, Gauss6 FullVA runtime drops from 3.408s dense to 0.109s CSR in the smooth case and from 2.838s dense to 0.129s CSR in the sharp case. The worst dense-vs-CSR final orientation difference across tested runs is 3.405e-23 rad, so the sparse solve preserves the trajectory to roundoff scale. Gauss4 remains too small for CSR to help, which supports a size-aware sparse/block policy.
- v032 tests matrix-free Newton-Krylov as the next way to avoid dense Jacobian materialization. The JAX JVP implementation is validated against dense Jacobian-vector products with relative errors 1.803e-16 in the smooth case and 5.233e-16 in the sharp case. However, unpreconditioned GMRES fails after 200 iterations on both single-step Gauss6 FullVA systems, with residual 1.323e+00 smooth and 1.574e+00 sharp, while the v031 CSR direct path succeeds in 0.017-0.023s. This rules out plain unpreconditioned JVP-GMRES as the immediate scaling fix and points to preconditioning or structured sparse/block assembly.
- v033 tests modified sparse Newton by lagging the CSR Jacobian for two Newton corrections or one full time step. The lagged variants are numerically safe on the targeted double-revolute runs: final orientation differences versus fresh CSR are around 1e-15, and endpoint velocity constraints remain unchanged. However, the speed result is mostly neutral or negative. Lagging reduces Jacobian evaluations by 1.45x-3.2x, but it increases Newton corrections enough that the best speedup is only 1.06x and most lagged variants are slower than fresh CSR. This rules out simple Jacobian lagging as the main scaling fix for the current benchmark.
- v034 tests structured sparse AD using column coloring and JAX JVPs. With a warm-up union sparsity pattern, the Gauss6 FullVA Jacobian has 582 nonzeros, about 3.06% density, and needs 11 colors. Colored JVP assembly matches dense Jacobian values to roundoff-level relative error: 1.932e-18 smooth and 1.003e-16 sharp, with no meaningful missed entries and trajectory differences at roundoff. It is still slower than dense `jacfwd` CSR on the 138D system: 0.428-0.432s versus 0.048-0.064s. This proves colored sparse AD is correct but says the next speed move should be hand/block assembly, compiled/batched coloring, or a larger topology where dense Jacobian memory/cost dominates.
- v035 tests the compiled/batched coloring option directly. It keeps the same 582-entry, 11-color warm-up sparsity pattern, but evaluates all color seed vectors in one `vmap(jvp)` call. This changes the sparse-AD conclusion from "correct but slow" to "correct and faster" on the current 138D double-revolute system: batched colored JVP runtime is 0.038s smooth and 0.035s sharp, versus dense `jacfwd` CSR at 0.102s and 0.088s. The dense-relative Jacobian error remains about 4.5e-18, and trajectory differences remain at roundoff scale. The remaining limitation is pattern acquisition: the mask still comes from a dense warm-up Newton path rather than symbolic/block sparsity.
- v036 removes that dense warm-up pattern dependency for the same Gauss6 FullVA double-revolute residual. It builds a conservative block-symbolic mask directly from the residual block structure. The mask is coarser than the warm-up union pattern, 1755 entries and 34 colors versus 582 entries and 11 colors, but it misses zero dense entries, matches dense Jacobian values to about 3.8e-18 relative error, and preserves the trajectory at roundoff scale. Pattern construction takes milliseconds instead of seconds. Runtime remains competitive despite the overpattern: sharp block-symbolic runtime is 0.050s versus dense `jacfwd` CSR at 0.079s, and smooth runtime is 0.077s versus dense 0.080s.
- v037 refines the v036 block-symbolic superset without dense Jacobian materialization. It uses batched JVPs along a short Newton/trajectory dry-run to prune inactive entries. In both smooth and sharp tests, the JVP-pruned pattern exactly matches the dense warm-up union pattern: 582 entries, 11 colors, zero extra entries, and zero missing entries. Pattern construction takes 0.053-0.067s, versus 0.952-1.082s for dense warm-up discovery in the recorded run. Dense Jacobians are used only after construction to verify missed entries and relative error, not to build the pattern.
- v038 tests pattern cache/reuse. One JVP-pruned pattern discovered from the smooth case over T=0.06 is reused over T=0.12 in both smooth and sharp cases. Dense validation patterns over the longer horizon still have 582 entries and 11 colors, and the cached pattern has zero missing entries in both cases. Runtime is dense `jacfwd` CSR 0.097s versus cached JVP-pruned 0.065s in smooth, and 0.101s versus 0.068s in sharp, giving 1.49x speedup in both longer runs.
- v039 moves the sparse-AD backend to a larger full-DAE topology: a three-body triple-revolute chain with Brown-McPhee friction at all hinges and a 207D Gauss6 FullVA Newton system. The JVP-pruned pattern has 930 entries and 11 colors, exactly matches dense validation in smooth and sharp cases with zero missing/extra entries, and gives 1.41x smooth plus 1.67x sharp runtime speedups versus dense `jacfwd` CSR. This is the first local evidence that the sparse-AD improvement transfers beyond the planar double-revolute benchmark.
- v040 removes v039's full-superset shortcut for the same triple-revolute topology. It generates a block-dependency superset with 2691 entries and 32 colors, verifies zero dense-validation misses, then uses batched JVP pruning to recover the exact 930-entry/11-color dense-validation pattern. Runtime is dense `jacfwd` CSR 0.104s versus block-pruned 0.049s smooth, and 0.088s versus 0.049s sharp. This makes the larger-topology sparse-AD result more production-like: dense Jacobians are still used for validation, not for pattern acquisition.
- v041 turns v040 into a cache refresh/union policy. A smooth short 930-entry/11-color cache is reused on longer nominal and perturbed smooth/sharp triple-revolute trajectories; generated-block refresh scans add zero entries and dense validation reports zero misses in all four natural scenarios. A stale-cache audit intentionally removes 23 entries, and the generated-block JVP refresh restores all 23 without dense Jacobians. Cached longer-run runtime remains 1.08x-1.54x faster than dense `jacfwd` CSR.
- v042 moves beyond planar/global-axis revolute geometry. Interbody axis constraints now align each child proximal axis to the parent body's distal axis, with skew body-fixed axes. The generated block superset has 2907 entries and 32 colors with zero dense-validation misses; JVP pruning recovers the exact 2181-entry/31-color dense-validation pattern. Endpoint velocity constraints are around 1e-16 after compatible initial interbody axis rates are enforced, and sparse runtime is 1.94x-1.98x faster than dense `jacfwd` CSR.
- v043 adds the first non-revolute lower-pair benchmark in this sequence: a skew-axis prismatic joint with five constraints, one free sliding coordinate, and Brown-McPhee-style sliding friction coupled to the normal load. The generated block superset has 1026 entries and 24 colors with zero dense-validation misses; JVP pruning recovers the exact 414-entry/18-color dense-validation pattern in both smooth and sharp cases. Dense and sparse trajectories match exactly and endpoint velocity constraints are about 1e-17. This is a correctness/coverage improvement, not a speed result, because sparse JVP assembly is slower than dense `jacfwd` on the 69D single-body system.
- v044 extends the prismatic test to a two-body chain with one ground prismatic joint and one interbody prismatic joint. The 138D FullVA residual has a generated block superset with 4824 entries and 90 colors, zero dense-validation misses, and an exact 2439-entry/90-color JVP-pruned pattern in both smooth and sharp cases. Dense and sparse trajectories match to roundoff and endpoint velocity constraints are about 1e-16. This confirms interbody non-revolute lower-pair correctness, but it is not yet a sparse-speed win: warmed dense/sparse runtime is 0.80x smooth and 0.87x sharp because the color count is too high.
- v045 tests row-colored batched VJP as a direct response to v044's 90-color column-JVP bottleneck. On the same 138D double-prismatic residual and exact 2439-entry sparse pattern, row coloring reduces seed directions from 90 to 54 and preserves dense-trajectory agreement to roundoff. Runtime improves only slightly versus column-JVP in the smooth case and ties in the sharp case, while still losing to dense `jacfwd`. This is useful negative/diagnostic evidence: for this prismatic chain, generic row coloring reduces colors but reverse-mode overhead remains too high.

- The representation/Jacobian bridge is now in place, Gauss6 is the current smooth-friction and smooth lambda-friction accuracy-per-cost winner, adaptive Gauss64 is the current high-accuracy near-nonsmooth regularized-friction winner, adaptive lambda-Gauss64 is the current high-accuracy multiplier-dependent sharp-friction winner, Brown-McPhee-style friction has been tested locally in both non-projection repair, v027 shows that adding pivot acceleration consistency tightens velocity drift to about 1e-12 without hurting Gauss6 trajectory accuracy, v028 shows explicit hinge-axis consistency is possible but neutral for the one-DOF trajectory, v029 shows the PivotVA repair transfers to an interbody revolute joint, v030 shows the next cost wall is sparse linear algebra rather than the small-system dynamics equations themselves, v031 confirms sparse Newton solves work inside the actual loop, v032 shows unpreconditioned matrix-free GMRES is not enough, v033 shows simple Jacobian lagging is not enough, v034 shows generic colored sparse AD is correct but not small-system fast, v035 shows compiled/batched colored sparse AD is both correct and faster than dense `jacfwd` on the current 138D benchmark, v036 shows dense warm-up pattern discovery can be replaced by a conservative block-symbolic mask, v037 recovers the exact observed fine pattern from that symbolic The remaining technical gap is now both formulation-level and validation-level: the path still needs component/block assembly for interbody prismatic patterns, mixed revolute-prismatic or cylindrical rotating-axis chains, contact/friction nonsmoothness, and larger skew-axis topologies before it can look like a production index-3 solver. After that, constrained BLieDF/RATTLie/generalized-alpha variants should be compared, especially in the sharp-friction regime where smooth collocation order stops being decisive.
